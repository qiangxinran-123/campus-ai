# CampusAI V0.1 Final Acceptance

Status: **Ready to mark complete**

CampusAI V0.1 is a backend-oriented prototype for university learning-material management and review assistance. This document records the final release-scope checks for the current version.

## Acceptance Checklist

| Area | Acceptance item | Result |
| --- | --- | --- |
| Application | FastAPI application starts from `backend.main:app`. | Pass |
| Courses | Courses can be listed and individual course details can be read. | Pass |
| Materials | Materials can be listed and created through the existing JSON API. | Pass |
| Persistence | Course and material changes are written to JSON and survive service restarts. | Pass |
| Upload | Supported course files can be uploaded into course-specific local directories. | Pass |
| Text extraction | `.txt` and `.md` uploads expose preview, length, and extraction status. | Pass |
| Mock summary | Text-backed materials can receive a persisted local mock summary. | Pass |
| Search | Materials can be searched by metadata, extracted text, or mock summary. | Pass |
| Study cards | Text-backed materials can receive three persisted mock review cards. | Pass |
| Compatibility | Old material records without newer optional fields remain readable. | Pass |
| Documentation | README, API overview, development log, and demo script are present. | Pass |
| Repository hygiene | Virtual environments, caches, environment files, and runtime uploads are ignored. | Pass |

## Repository Hygiene

- `backend/app/data/courses.json` remains as the small example data set.
- `.venv/`, Python caches, `.pytest_cache/`, local environment files, and runtime uploads are excluded by `.gitignore`.
- Real user-uploaded files are not part of the release tree.
- Test data and upload files are created in temporary directories by the integration suite.

## Current Limitations

- Storage is local JSON rather than a database.
- Summary and study-card generation are deterministic local mock services, not real LLM calls.
- Rich text extraction currently supports `.txt` and `.md`; other accepted upload formats are stored but not parsed.
- There is no frontend, authentication, multi-user ownership, or collaboration layer yet.
- The current upload and JSON persistence flow is intended for a small prototype, not high-concurrency production use.

## Next Version Planning

- Integrate a real LLM behind the existing summary and card service boundaries.
- Add embeddings, RAG retrieval, and a vector database.
- Add PDF, PowerPoint, and Word text extraction.
- Build a student-facing frontend with course and review-card views.
- Add authentication, user ownership, database persistence, and asynchronous processing.

## Release Decision

The V0.1 release scope is complete when the test command passes, the repository contains only intentional source/data/documentation files, and the latest commit is pushed to `origin/main`.
